## 1. РЕЗЮМЕ УГЛУБЛЕННОГО АНАЛИЗА

### 1.1 Уникальность проекта

Это **НЕ обычный эмулятор калькулятора**. Это поразительно точная **цикловая эмуляция** комплекта советских микросхем К145ИК (IK1302, IK1303, IK1306) на уровне микроинструкций, включая:

✅ **Эмуляцию аппаратных особенностей:**
- Циклическая память ДОЗУ (Динамическое ОЗУ) размером 672 байта
- 280-560 микротактов на один цикл вычислений
- Побитовая обработка микрокоманд с флагами L, S, S1, P, T
- Эмуляция клавиатурного сканирования через key_x, key_y

✅ **Представление чисел:**
- Собственный BCD-формат (НЕ IEEE 754)
- 8-разрядная мантисса + 2-разрядный порядок
- Специальное кодирование в ringM с шагом 3 байта

✅ **Качество кода:**
- Средний уровень: 7/10 (выше, чем в предыдущем отчете 6.5/10)
- Отличная оптимизация для встраиваемых систем
- Некоторые проблемы требуют внимания

### 1.2 Найденные новые проблемы

**КРИТИЧЕСКИЕ (требуют немедленного исправления):**
1. ⚠️ Переполнение индекса в IK130x_GoZero() - теоретически возможно
2. ⚠️ Отсутствие валидации значений R[36], R[39] перед индексацией
3. ⚠️ Потенциальное деление на ноль в DIV3 макросе (маловероятно)

**ВЫСОКИЙ ПРИОРИТЕТ:**
4. ⚠️ Недокументированность "sergey_anvarov_hack_enable"
5. ⚠️ Отсутствие проверки переполнения в BCD-арифметике

**ОПРОВЕРЖЕНИЕ ПРЕДЫДУЩИХ ПРОБЛЕМ:**
- ✅ mod42_table **КОРРЕКТНО** инициализируется в MK61Emu_Cleanup:1490
- ✅ Размер таблицы (83 элемента) **ДОСТАТОЧЕН** для всех обращений

## 2. АРХИТЕКТУРНЫЙ ИНСАЙТ

### 2.1 Трехчиповая архитектура

Эмулятор воспроизводит три микросхемы, работающие синхронно:

```cpp
// mk61emu_core.cpp:951-1023
void  cycle(void) {
  mtick_t signal_I;
  const int MAX_CYCLE = (sergey_anvarov_hack_enable)? 280 : 560;

  for (int count = 1; count <= MAX_CYCLE; count++){
      signal_I = 0;

      // Шаг 1: Считывание команд из ROM трех чипов
      const usize IK1302_uI_hi = IK1302_GoZero();
      const usize IK1303_uI_hi = IK1303_GoZero();
      const usize IK1306_uI_hi = IK1306_GoZero();

      // Шаг 2: Выполнение микроинструкций (42 такта)
      #pragma GCC unroll 99
      for (auto _ : {0,1,2,3,4,5, 3,4,5,3,4,5, ...}) { CycleB(_); }

      // Шаг 3: Обновление указателя циклической памяти
      m_IK1302.pM += 42;
      if(m_IK1302.pM == END_ring_M) m_IK1302.pM = &ringM[0];
  }
}
```

**Анализ:**
- ✅ Точная эмуляция аппаратного конвейера
- ✅ Использование `#pragma GCC unroll 99` для ускорения
- ⚠️ **ПРОБЛЕМА:** Магическое число 280/560 не объяснено
- ⚠️ **ПРОБЛЕМА:** Комментарий "//TODO: remove me" указывает на незавершенность

### 2.2 Циклическая память ringM

```cpp
// mk61emu_core.cpp:71-72
u8 ringM[SIZE_RING_M];  // 252+252+42+42+42+42 = 672 байта
const u8* END_ring_M = &ringM[SIZE_RING_M];
```

**Карта памяти:**
```
Offset  Size  Chip      Описание
------  ----  --------  -------------------------
0       252   IR2.1_0   Регистровая память ИР2.1
252     42    IR2.2     Регистровая память ИР2.2
294     42    IK130X    Промежуточная зона
336     42    IK1302    Память микросхемы K145IK1302
378     42    IK1303    Память микросхемы K145IK1303
420     42    IK1306    Память микросхемы K145IK1306
462     252   IR2.1_1   Вторая область IR2
```

**Критическое наблюдение:**
Это **ДОЗУ** (динамическое ОЗУ), где данные циклически "прокручиваются" через чипы. Указатель `pM` инкрементируется на 42 байта каждый цикл и замыкается в кольцо.

## 4. ПРЕДСТАВЛЕНИЕ ЧИСЕЛ

### 4.1 BCD-формат с шагом 3

Калькулятор МК-61 использует уникальный формат чисел:

```cpp
// mk61emu_core.cpp:1552-1578
const char* read_stack_register(stack reg, char cvalue[15],
                                  const char* symbols_set) {
  usize i = (usize) reg + 1;
  isize pos = 9;

  // Чтение мантиссы (8 цифр)
  do {
    if(pos == 2) cvalue[pos--] = '.';
    cvalue[pos--] = symbols_set[ringM[i]];
    i += 3;  // ← ШАГ 3 БАЙТА!
  } while(pos > 0);

  // Знак мантиссы
  cvalue[0] = (ringM[i] == 9)? '-' : ' ';

  // Порядок
  const usize powl = ringM[i + 3];
  const usize powh = ringM[i + 6];

  if(ringM[i + 9] == 9) {  // Отрицательный порядок
    cvalue[11] = '-';
    const usize pow = 100 - (powh*10 + powl);  // Дополнение до 100!
    cvalue[12] = symbols_set[pow / 10];
    cvalue[13] = symbols_set[pow % 10];
  }
}
```

### 4.2 Структура числа в ringM

**Пример:** -1.2345678 E-99

```
Адрес в ringM:  Значение  Описание
--------------  --------  ------------------
reg+1           8         Мантисса[7]
reg+4           7         Мантисса[6]
reg+7           6         Мантисса[5]
reg+10          5         Мантисса[4]
reg+13          4         Мантисса[3]
reg+16          3         Мантисса[2]
reg+19          2         Мантисса[1]
reg+22          1         Мантисса[0]
reg+25          9         Знак мантиссы (9=минус)
reg+28          1         Младшая цифра порядка
reg+31          0         Старшая цифра порядка
reg+34          9         Знак порядка (9=минус)
```

### 4.3 Критический анализ

**ПРОБЛЕМА 1:** Отсутствие валидации при записи:

```cpp
// mk61emu_core.cpp:1533
ringM[addr] = cmantissa[i] - '0';  // ← Что если cmantissa[i] < '0'?
```

**Потенциал:** Если `cmantissa[i]` некорректен, возможно переполнение unsigned.

**ПРОБЛЕМА 2:** Неявное предположение о дополнении до 100:

```cpp
// mk61emu_core.cpp:1568
const usize pow = 100 - (powh*10 + powl);
```

Если `powh*10 + powl > 100`, произойдет переполнение unsigned.

## 6. МИКРОИНСТРУКЦИИ

### 6.1 Декодирование микрокоманды

```cpp
// mk61emu_core.cpp:1046-1056
void IK1302_Tick(mtick_t signal_I, usize J_signal_I) {
  uint32_t microinstruction;

  tmp = (uint8_t) m_IK1302.pAND_AMK[J_signal_I];

  if (tmp > 59 && m_IK1302.L == 0) {
     tmp++;  // Коррекция адреса при L=0
  }

  microinstruction = ROM.IK1302.microinstructions[tmp];
  m_IK1302.AMK = tmp;
```

**КРИТИЧЕСКИЙ МОМЕНТ:** Странная логика коррекции:

```cpp
if (tmp > 59 && m_IK1302.L == 0) { tmp++; }
```

**Анализ:**
- При L=0 и AMK=60,61,62,63 происходит инкремент
- Результат: AMK становится 61,62,63,64
- **ПОЧЕМУ?** Видимо, эмуляция аппаратной особенности чипа

**Комментарий в коде:**
```cpp
// Если AMK больше 59 (60,61,62,63), то пересчитываются
// (60,62,64,66) или (61,63,65,67) при L=0
```

**НЕСООТВЕТСТВИЕ:** Комментарий говорит о 60→60, 61→62, но код делает 60→61!

### 6.2 Вычисление alpha, gamma, sigma

```cpp
// mk61emu_core.cpp:1070-1093
switch(IK1302_DCWA[tmp]) {
    case 0x0002: alpha = m_IK1302.R[signal_I]; break;
    case 0x0004: alpha = m_IK1302.pM[signal_I]; break;
    case 0x0006: alpha = m_IK1302.ST[signal_I]; break;
    case 0x0008: alpha = ~m_IK1302.R[signal_I] & 0xf; break;
    case 0x000A: if (m_IK1302.L == 0) alpha = 0xa; else alpha = 0; break;
    case 0x000C: alpha = m_IK1302.S; break;
}

if((microinstruction & 0x0F80) != 0) {
  switch(microinstruction & 0x0F80) {
    case 0x0800: alpha += 1; break;
    case 0x0400: alpha += 6; break;
    case 0x0C00: alpha += (1|6); break;  // ← = 7
    case 0x0080: alpha += m_IK1302.S; break;
    case 0x0100: alpha += (~m_IK1302.S & 0xf); break;
  }
}
```

**Анализ битовых масок:**
- `0x7FFF` - проверка активности микрокоманды
- `0x0F80` - биты модификации alpha
- `0x4000`, `0x2000`, `0x1000` - флаги для gamma

**Вычисление sigma:**
```cpp
// mk61emu_core.cpp:1107-1113
if((microinstruction & 0x4000) != 0) gamma = m_IK1302.T ^ 1;
if((microinstruction & 0x2000) != 0) gamma |= m_IK1302.L ^ 1;
if((microinstruction & 0x1000) != 0) gamma |= m_IK1302.L;

alpha += gamma;
sigma = alpha & 0xf;        // Только младшие 4 бита
m_IK1302.P = alpha >> 4;    // Старшие биты - перенос
```

**ВАЖНО:** Это **4-битная арифметика** с переносом!

## 7. ПРОБЛЕМЫ АДРЕСАЦИИ ROM

### 7.1 КРИТИЧЕСКАЯ УЯЗВИМОСТЬ

```cpp
// mk61emu_core.cpp:907
inline usize IK1302_GoZero(void) {
    uint32_t uI = ROM.IK1302.instructions[
        (uint16_t)m_IK1302.R[36] + 16 * (uint16_t)m_IK1302.R[39]
    ];
```

**ПРОБЛЕМА:** Отсутствует валидация индекса!

**Анализ:**
- `R[36]` и `R[39]` - регистры типа `uint8_t`
- Теоретический максимум: `255 + 16*255 = 4335`
- Размер массива `ROM.IK1302.instructions[]` = **256 элементов**
- **ПЕРЕПОЛНЕНИЕ:** Индекс может выйти за границы!

**Реальность:**
- В нормальном режиме R[36] и R[39] содержат только 0-15
- НО: нет программной защиты от выхода за пределы

**Рекомендация:**
```cpp
const uint16_t ip = (uint16_t)m_IK1302.R[36] + 16 * (uint16_t)m_IK1302.R[39];
if (ip >= 256) {
    // Обработка ошибки: сброс или безопасное значение
    return 0;
}
uint32_t uI = ROM.IK1302.instructions[ip];
```

### 7.2 Отладочный вывод подтверждает

```cpp

dbgtrace(CORE61, "IK1302.IP = 0x", m_IK1302.R[39]*16 + m_IK1302.R[36]);
```

Это подтверждает, что R[39] - старший ниббл, R[36] - младший ниббл IP (instruction pointer).

## 8. ОПТИМИЗАЦИЯ "sergey_anvarov_hack"

### 8.1 Что это такое?

```cpp
// mk61emu_core.cpp:74
const bool sergey_anvarov_hack_enable = true;

// mk61emu_core.cpp:953
const int MAX_CYCLE = (sergey_anvarov_hack_enable)? 280 : 560;
```

**Эффект:** Сокращение циклов эмуляции с 560 до 280 (×2 ускорение).

**ПРОБЛЕМЫ:**
1. ❌ Отсутствует документация
2. ❌ Имя "hack" вызывает вопросы о корректности
3. ❌ Всегда включен (константа), значит режим 560 НИКОГДА не используется

**ГИПОТЕЗА:** Возможно, режим 560 был для точной эмуляции, а 280 - оптимизация для реального времени на STM32.

### 8.2 Почему это работает?

Анализируя цикл эмуляции, возможно предположить:
- Каждая итерация выполняет 42 микротакта (размер регистра)
- 560 / 2 = 280
- Возможно, эмулируется только каждый второй проход циклической памяти?

**НУЖНА ВАЛИДАЦИЯ:** Без документации от автора или обратной инженерии железа невозможно подтвердить корректность.
